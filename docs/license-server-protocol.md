# Протокол доски с сервером ключей

Раздел 9.1 задания: **доска не хранит паролей Робокассы и не общается с
Робокассой напрямую.** Счёт заводит сервер ключей `keys.school-pi.online`,
он же принимает уведомление об оплате и сообщает доске, что счёт оплачен.

Этот документ — описание протокола со стороны доски. Доработка самого
сервера ключей — отдельная задача; здесь только то, что от него нужно.

## Зачем так

У сервера ключей уже есть своя последовательность номеров счетов и вся
платёжная обвязка. Заведи доска свой номер счёта — Робокасса прислала бы
уведомление о счёте, которого сервер ключей не знает: человек заплатил бы
и не получил ничего. По той же причине на сайте нет промежуточного
обработчика оплаты.

```
доска  ──①──►  сервер ключей ──►  Робокасса
                     ▲                 │
                     └───────②─────────┘
доска  ◄──③──  сервер ключей
```

① доска просит счёт · ② Робокасса сообщает об оплате серверу ключей ·
③ сервер ключей сообщает доске

## ① Запрос счёта

Доска → сервер ключей, когда преподаватель выбрал срок подписки.

```
POST https://keys.school-pi.online/billing/invoice
Content-Type: application/json
X-Signature: <подпись тела>
```

```json
{
  "product": "board",
  "userId": 42,
  "email": "prepodavatel@example.com",
  "planCode": "base",
  "days": 90,
  "amount": 900.00,
  "returnUrl": "https://board.school-pi.online/subscribe/done"
}
```

`product` обязателен: сервер ключей обслуживает и лицензии десктопной
доски, и подписки веб-доски, и по этому полю отличает одно от другого.

Ответ:

```json
{ "invoiceId": "12345", "paymentUrl": "https://auth.robokassa.ru/..." }
```

Доска запоминает `invoiceId` и уводит человека по `paymentUrl`.

## ③ Обратный вызов об оплате

Сервер ключей → доска, после того как Робокасса подтвердила оплату.

```
POST https://board.school-pi.online/api/billing/paid
Content-Type: application/json
X-Signature: <подпись тела>
```

```json
{
  "invoiceId": "12345",
  "userId": 42,
  "planCode": "base",
  "days": 90,
  "paidAt": "2026-08-26T10:15:00Z"
}
```

Ответ доски: `200 OK` с телом `{"status":"ok"}`. Любой другой ответ сервер
ключей должен считать неудачей и повторить вызов позже.

## Подпись

Обе стороны подписывают тело запроса общим секретом `LICENSE_SHARED_SECRET`,
который лежит в `.env` обеих служб и больше нигде.

```
X-Signature = hex( HMAC-SHA256( ключ = LICENSE_SHARED_SECRET, данные = тело запроса ) )
```

Подписывается **байт в байт то тело, которое ушло в сеть** — не результат
повторной сериализации разобранного JSON: порядок полей и пробелы при
этом меняются, и подпись перестаёт сходиться.

Запрос без верной подписи — отказ `401`, без разбора тела. Сравнение
подписей за постоянное время: обычное сравнение строк выдаёт длину
совпавшего префикса через время ответа.

## Повторный вызов не должен продлевать подписку дважды

Сервер ключей повторяет обратный вызов, пока не получит `200` — значит,
один и тот же `invoiceId` придёт не один раз. Это норма, а не сбой связи.

Защита — уникальный индекс на `Subscriptions.invoice_id`, а не проверка
«есть ли уже такая запись» перед вставкой: между проверкой и вставкой
проходит время, и два одновременных вызова успевают пройти проверку оба.
Повторная вставка нарушает индекс, доска ловит это и отвечает `200`, потому
что для сервера ключей результат достигнут — подписка продлена.

## Как считается срок

Раздел 9.3: продление **прибавляет дни к концу текущего периода**, а не
обнуляет его.

- подписка действует (`ends_at > now`) → новый период начинается с `ends_at`;
- не действует → с текущего момента.

Пробный период тем же правилом покрывается сам собой: покупка во время
пробного не съедает его остаток, потому что `ends_at` пробного лежит в
будущем и новый период начинается от него (раздел 9.2).

## Чего в протоколе нет намеренно

**Возврата средств.** Возврат проводится в кабинете Робокассы вручную;
автоматически отменять подписку по возврату доска не умеет и не должна —
это редкий случай, требующий человеческого решения.

**Автопродления.** Раздел 12 выносит его за рамки. Модель данных ему не
мешает: `invoice_id` у каждого периода свой, и добавление регулярных
списаний не потребует переделки таблиц.

**Проверки лицензионных ключей десктопной доски.** Это другой продукт,
доска к нему не обращается.
