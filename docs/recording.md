# Запись занятия — описание реализации (онлайн-доска)

Документ описывает, как устроена запись занятия в онлайн-версии «Доски Пи»
после правок сентября 2026 года, — подробно, чтобы по нему можно было
повторить то же поведение в ПК-версии. Где это важно, приведены имена
файлов и методов онлайн-версии; для переноса они не обязательны —
обязательны правила, описанные словами.

---

## 1. Что такое запись

Запись — **не видео**, а последовательность событий доски с отметками
времени: «начали штрих», «добавили точки», «закрепили объект», «сдвинули»,
«удалили», «сменили фон», «ведущий сдвинул вид» и т. д. Воспроизведение —
это те же события, применённые к пустому холсту в том же темпе.

Отсюда следствия:

- запись маленькая (килобайты–мегабайты, а не сотни мегабайт видео);
- при просмотре картинка чёткая при любом масштабе;
- звука в записи нет;
- пустое время (никто ничего не делал) в записи есть — оно просто
  «стоит»; время на **паузе** в запись не попадает вовсе (см. §3.2).

---

## 2. Кто попадает в запись

**Действия всех участников, а не только ведущего.** Сервер дописывает в
идущую запись каждое событие доски, от кого бы оно ни пришло
(`BoardHub.PublishAsync` → `BoardRecordingService.AppendStepAsync`):
если одновременно рисуют ведущий и два ученика — в записи будут штрихи
всех троих, в том порядке и темпе, в каком они появлялись.

**Вид (страница, положение, масштаб) — только ведущего.** Запись смотрят
«глазами ведущего»: при просмотре холст сам ездит и масштабируется так,
как ездил у него. Вид учеников не записывается.

Что именно записывается (имена событий — как в онлайн-версии):

| Событие | Что это | Кто порождает |
|---|---|---|
| `ViewportChanged` | вид ведущего: `pageId`, центр `x`/`y` в мировых координатах, `scale`, размер видимой части холста `width`×`height` в экранных точках | только ведущий, не чаще раза в 300 мс |
| `PageShown` | ведущий открыл другую страницу: `pageId` и **всё её содержимое** на этот момент (`items`) | только ведущий |
| `ItemBegan` | начало штриха (рисуется «вживую») | любой рисующий |
| `ItemPoints` | новые точки штриха | любой рисующий |
| `ItemCancelled` | штрих отменён (например, начался жест двумя пальцами) | любой |
| `ItemCommitted` | объект закреплён (штрих, фигура, текст, картинка, таблица, закладка) | любой |
| `ItemUpdated` | объект изменён (текст, цвет, толщина, размер, поворот) | любой |
| `ItemsMoved` | объекты сдвинуты на `dx`, `dy` | любой |
| `ItemsReordered` | порядок слоёв | любой |
| `ItemsDeleted` | удаление (в т. ч. ластиком — см. ниже) | любой |
| `BoardCleared` | страница очищена | ведущий |
| `BackgroundChanged` | фон / разлиновка | ведущий |

Не записываются курсоры участников — они идут отдельным потоком, мимо
журнала событий.

Сервер пишет в запись **все** события журнала доски, в том числе
служебные — вход и выход участников (`MemberJoined`, `MemberLeft`), замки
объектов на время правки (`ItemLocked`, `ItemUnlocked`). Проигрыватель
их просто пропускает. Указка (лазер) — это обычный штрих с пометкой
`laser`, который никогда не закрепляется: в записи он виден как линия,
которая рисуется и через ~2,2 с пропадает (`ItemBegan` → `ItemPoints` →
`ItemCancelled`), без плавного угасания, как на живой доске. При
переносе стоит решить: либо так же, либо рисовать её в проигрывателе
угасающим следом.

Ластик: проход ластиком приходит одним пакетом при отпускании — `ItemsDeleted`
задетых штрихов и `ItemCommitted` их оставшихся кусков. В записи это
выглядит как «стёрлось сразу по отпусканию», а не по ходу движения.

## 3. Данные

### 3.1. Запись (`BoardRecording`)

| Поле | Смысл |
|---|---|
| `Id` | номер |
| `BoardId` | доска |
| `StartedByUserId` | кто начал (всегда владелец доски) |
| `Title` | название; пусто — показывается дата начала |
| `Status` | `recording` — идёт; `paused` — на паузе; `stopped` — закончена |
| `StartedAt`, `EndedAt` | начало и конец (UTC) |
| `DurationMs` | накопленное время **без пауз** |
| `LastResumedAt` | когда начался текущий отрезок записи; пусто на паузе и после остановки |
| `MaxDurationMs` | потолок длительности по тарифу **на момент старта** |

Незавершённая (`recording` или `paused`) запись на доске может быть только
одна.

### 3.2. Время и пауза

Смещение шага от начала записи:

```
offsetMs = DurationMs + (сейчас − LastResumedAt)   // если идёт
```

- **Пауза**: `DurationMs += сейчас − LastResumedAt`, `LastResumedAt = null`,
  статус `paused`. Время записи стоит.
- **Продолжить**: статус `recording`, `LastResumedAt = сейчас`.
- **Стоп**: то же, что пауза, плюс статус `stopped`, `EndedAt = сейчас`.

**Пауза — только вырезка времени, а не «не смотреть».** Всё, что сделали
на паузе, в запись попадает, но без процесса — одним результатом в той
отметке, где запись встала:

- **пишутся** на паузе: `ItemCommitted`, `ItemUpdated`, `ItemsMoved`,
  `ItemsReordered`, `ItemsDeleted`, `BoardCleared`, `BackgroundChanged`
  (и служебные) — все с `OffsetMs = DurationMs` (время стоит);
- **не пишутся** на паузе: `ItemBegan`, `ItemPoints`, `ItemCancelled` —
  процесс рисования показывать незачем;
- вид ведущего на паузе не пишется по ходу, но в момент продолжения
  клиент сразу сообщает текущий вид — он ложится в ту же отметку.

При просмотре: запись доходит до места паузы, и в это мгновение разом
появляется всё, что нарисовали, сдвинули или стёрли на паузе, — дальше
идёт продолжение. Пустых минут паузы в записи нет, а содержимое записи
не расходится с доской. (Онлайн — `BoardRecordingService.AppendStepAsync`.)

Потолок тарифа: если `offsetMs ≥ MaxDurationMs`, шаг не пишется, а запись
останавливается.

### 3.3. Шаг (`BoardRecordingStep`)

| Поле | Смысл |
|---|---|
| `RecordingId` | запись |
| `OffsetMs` | смещение от начала записи (без пауз) |
| `Name` | имя события (таблица в §2) |
| `Payload` | JSON события — **ровно тот же**, что уходит живым участникам (camelCase) |

Порядок шагов — по возрастанию номера (порядок вставки). Одинаковый
`OffsetMs` у нескольких шагов — нормально (стартовое состояние, §4.2).

## 4. Старт записи

### 4.1. Что видит ведущий

1. Открывает панель записей, по желанию вводит название и ставит галочку
   «Начать с того, что уже нарисовано на странице», жмёт «Начать запись».
2. Панель закрывается. **Слева от кнопки «Участники»** (правый нижний
   угол холста) появляется блок с **отсчётом 3 → 2 → 1** крупной цифрой
   по центру, по секунде на цифру. Блок уже с **зелёным фоном и рамкой**
   (как у идущей записи, см. §6), но **без мерцания** — оно появится,
   когда запись реально пойдёт.
3. После «1» (через 3 с от нажатия) на месте цифры появляются две
   кнопки — **Пауза** и **Стоп** — в мерцающем зелёном блоке. С этого
   мгновения записывается всё.

Что нарисовали во время отсчёта, в записи будет — но как результат в
нулевой секунде, без процесса (отсчёт — это та же пауза, §3.2).

Смысл отсчёта: раньше кнопка менялась только после ответа сервера
(доли секунды — секунда), и то, что ведущий успевал нарисовать сразу
после нажатия, в запись не попадало, хотя он уже считал её идущей.
Отсчёт честно показывает, когда начинать.

### 4.2. Что происходит внутри

```
Ведущий жмёт «Начать запись»
  │
  ├─► клиент сразу: countdown = 3 (показ 3, 2, 1)
  │
  └─► сервер: StartRecording(title, seedExisting, pageId, x, y, scale, width, height)
        │   pageId, x, y, scale — вид ведущего в момент нажатия
        │   (x, y — мировые координаты центра видимой части холста);
        │   width, height — размер этой видимой части в экранных точках
        │
        ├─ проверки: владелец? нет ли уже незавершённой записи? лимит тарифа?
        │     нет → ошибка «recording» с текстом, отсчёт на клиенте гасится
        │
        ├─ создаётся запись со статусом **paused**, DurationMs = 0,
        │  LastResumedAt = пусто
        │
        ├─ в неё ОДНИМ пакетом, все с OffsetMs = 0, пишется
        │  стартовое состояние («seed»):
        │    1. ViewportChanged { pageId, x, y, scale, width, height } ← всегда, первым
        │    2. BackgroundChanged { фон, разлиновка, цвет линий }      ← всегда
        │    3. ItemCommitted × N — всё, что лежит на странице      ← если галочка
        │       (tempId = "seed-<id>", by = "seed")
        │
        └─ всем на доске: RecordingStarted { id, title, startedAt, status: "paused" }

Через 3 с на клиенте ведущего отсчёт кончился
  └─► сервер: ResumeRecording()  → статус recording, LastResumedAt = сейчас
        └─ всем: RecordingResumed
```

Почему так:

- **Seed в нулевую миллисекунду одним пакетом.** Раньше уже нарисованное
  дописывалось шагами по одному, каждый со своей записью в базу, — и
  получал растущую отметку времени. При просмотре старое содержимое
  быстро «дорисовывалось» в первые секунды. Теперь оно всё в кадре с
  первого же мгновения.
- **Вид ведущего — первым шагом seed.** Раньше вид приходил в запись
  позже, отдельным сообщением клиента, и первые кадры показывались в
  автоподгонке под содержимое, а потом «переезжали». Теперь вид задан
  с нулевой миллисекунды. Первым — ещё и потому, что проигрыватель
  отбрасывает объекты не с той страницы, а страницу он узнаёт из вида.
- **Старт на паузе.** Пока идёт отсчёт, время записи не течёт и ничего
  не пишется. В записи нет трёх пустых секунд отсчёта, а всё, что
  нарисуют сразу после «1», попадает в запись.
- **Паузу снимает клиент по концу отсчёта**, а не сервер по таймеру:
  на сервере не нужно держать таймеры на каждую запись, и отсчёт на
  экране и реальный старт совпадают.

Тонкости клиента (`BoardPage.tsx`):

- Если к концу отсчёта подтверждение (`RecordingStarted`) ещё не пришло,
  клиент ставит флаг «снять паузу, когда придёт» и держит его 5 секунд;
  не пришло — флаг сбрасывается (значит, сервер отказал).
- Если во время отсчёта пришла ошибка, а записи так и нет — отсчёт
  гасится сразу.
- Другие участники видят запись с момента `RecordingStarted`: сначала
  «на паузе» (голубой, §6), по концу отсчёта — «идёт» (зелёный).
- Вид ведущего пишется и дальше, по ходу записи: при каждом его сдвиге
  или масштабе, не чаще раза в 300 мс (`ReportViewport`, только
  владелец, только пока статус `recording`).

## 5. Пауза, продолжение, стоп — вручную и автоматически

### 5.1. Вручную

Кнопки в блоке записи слева от «Участников» (§6): **Пауза** /
**Продолжить** и **Стоп**. Стоп сохраняет запись (статус `stopped`), и
блок исчезает.

### 5.2. Автоматически

| Ситуация | Что происходит | Как устроено |
|---|---|---|
| Ведущий **перезагрузил** страницу | идущая запись встаёт на **паузу**; после перезагрузки остаётся на паузе, продолжают кнопкой | клиент на `pagehide` шлёт `PauseRecording` (без ожидания ответа); запасной путь — при первом входе после перезагрузки той же доски, если запись всё ещё «идёт», клиент ставит её на паузу |
| Ведущий **ушёл с доски внутри сайта** («Мои доски», «Выйти» и т. п.) | запись **останавливается и сохраняется** (и идущая, и на паузе) | при размонтировании страницы доски клиент вызывает `StopRecording`, и только потом закрывает соединение |
| Ведущий **закрыл вкладку/браузер** или пропал со связи | сначала **пауза**, а если он не вернулся за **3 минуты** — **стоп и сохранение** | фоновая служба `RecordingWatchdog` раз в 30 с проверяет незавершённые записи: ведущего (тот, кто начал) нет на доске → пауза; нет дольше 3 мин → стоп. Вернулся — отсчёт ухода сбрасывается |
| Достигнут потолок тарифа по длительности | стоп | при попытке дописать шаг сверх `MaxDurationMs` |

Перезагрузку и закрытие вкладки браузер по отдельности не различает — оба
случая одинаково «страница исчезает». Поэтому для обоих сначала пауза, а
окончательное решение (вернулся ли человек) принимает сервер по времени.

## 6. Кнопки записи — состояния и оформление

Два места:

- **Верхняя панель**, между «Таймером» и «Фоном», — всегда одна и та же
  кнопка «Записи занятия» (кружок в кольце), без подсветки. Она только
  открывает панель записей: начать запись, список, просмотр.
- **Блок записи слева от «Участников»** (правый нижний угол холста) —
  появляется, как только нажали «Начать запись», и исчезает по стопу.
  Верхнюю панель на телефоне листают вбок и прячут, а идущую запись должно
  быть видно всегда, поэтому управление вынесено сюда.

Блок записи стоит **вне потока**: кнопка «Участники» не сдвигается ни при
его появлении, ни когда вместо цифры появляются две кнопки (онлайн —
`position: absolute; right: calc(100% + 8px)` относительно угла с
«Участниками», по вертикали — по центру).

| Состояние | Что в блоке | Оформление блока |
|---|---|---|
| записи нет | блока нет | — |
| отсчёт перед стартом | крупная цифра 3 / 2 / 1 зелёного цвета, ровно по центру квадрата 44×44 | светло-зелёный фон и рамка, **без мерцания** |
| идёт запись | две кнопки: «Пауза» и «Стоп» | светло-зелёный фон и рамка, **фон плавно мерцает** |
| пауза | две кнопки: «Продолжить» и «Стоп» | светло-голубой фон и рамка, **ровный** |

Точные значения (онлайн-версия, CSS):

- «зелёный» — цвет `--success` темы (`#3A6B3C` светлая, `#8FC490` тёмная);
  рамка — 45 % этого цвета, фон — 14 %;
- мерцание — плавная смена фона 8 % → 30 % → 8 %, период **2 с**,
  `ease-in-out`, бесконечно; при системной настройке «уменьшить
  движение» — без анимации;
- «голубой» — цвет `--info` (`#2A4E8F` / `#93A4F2`); рамка 55 %, фон 20 %;
- блок — скругление как у кнопок, внутренний отступ 1 px, кнопки внутри
  через 2 px, лёгкая тень;
- фон блока **непрозрачный** — под ним рисунок доски: оттенки смешаны не
  с прозрачностью, а с цветом панели (`color-mix(… 14 %, surface)`), и
  мерцание — так же, между 8 % и 30 % на цвете панели;
- кнопки внутри блока при наведении и нажатии подсвечиваются **тем же
  цветом блока, только гуще** (зелёный 30 %, голубой 35 %), а не общим
  серым. На сенсорном экране подсветка только пока палец держит кнопку —
  «залипшего» наведения нет.

У участников, которые запись не ведут, в блоке слева от «Участников» —
одна метка (кружок записи; на паузе — значок паузы) в том же блоке:
зелёный мерцающий, пока идёт запись, голубой на паузе; нажатие открывает
панель записей. Отсчёт видит только ведущий — остальные в это время
видят «на паузе». Гостям без учётной записи блок не показывается.

## 7. Воспроизведение

Проигрыватель (`RecordingPlayer.tsx`, логика шагов — `replay.ts`).

### 7.1. Состояние воспроизведения

```
PlaybackState {
  items: объекты на холсте
  live:  штрихи, которые рисуются прямо сейчас (tempId → штрих)
  background: фон и разлиновка
  viewport: вид ведущего { pageId, x, y, scale } или пусто
}
```

`applyRecordedStep(state, name, payload)` — **чистая функция**: та же
логика, что у живой доски, но без побочных эффектов, чтобы можно было
перематывать туда и обратно.

Правила применения:

- `ViewportChanged` — заменить вид.
- `ItemBegan` — если вид задан и страница не та → пропустить; иначе
  добавить в `live`.
- `ItemPoints` — дописать точки к штриху в `live`.
- `ItemCancelled` — убрать из `live`.
- `ItemCommitted` — убрать из `live`; если страница не та → больше
  ничего; иначе заменить/добавить объект по `id`.
- `ItemsMoved` — сдвинуть объекты с этими `id` на `dx`, `dy`.
- `ItemsReordered` — подменить объекты и пересортировать по `z`, затем `id`.
- `ItemUpdated` — подменить объект по `id`.
- `ItemsDeleted` — убрать объекты с этими `id`.
- `BoardCleared` — если страница та → очистить объекты и `live`.
- `PageShown` — заменить объекты содержимым из шага, очистить `live`, в
  виде сменить `pageId` (точные центр и масштаб придут следующим
  `ViewportChanged`). Без этого шага проигрыватель после перехода
  ведущего на другую страницу показывал бы объекты старой, а того, что на
  новой нарисовано раньше, не показывал бы вовсе.
- `BackgroundChanged` — заменить фон.

### 7.2. Время и перемотка

- Текущая позиция `offsetMs`. При воспроизведении она растёт от
  отметки реального времени (`performance.now()`), а не накоплением
  кадров, — фоновая вкладка не тормозит счёт.
- На каждый кадр применяются все шаги с `OffsetMs ≤ offsetMs`, которые
  ещё не применены. Состояние кэшируется: вперёд — донакапливаем, назад
  (перемотка влево) — собираем заново с начала.
- **В позиции 0 уже применён весь seed** (у него `OffsetMs = 0`): первый
  кадр — сразу стартовое содержимое в виде ведущего.
- Длительность — `DurationMs` записи.

### 7.3. Отрисовка кадра

1. Холст проигрывателя — в настоящих пикселях экрана (`× devicePixelRatio`),
   иначе на телефоне запись мутнее самой доски.
2. Залить фон, нарисовать разлиновку — фон и разлиновка из записи, как у
   ведущего (в записи они есть всегда, §4.2).
3. Вид: окно проигрывателя почти всегда другого размера, чем экран
   ведущего (сверху заголовок, снизу перемотка), — поэтому видимая им
   область **вписывается целиком**:

   ```
   fit     = min(ширина окна / width, высота окна / height)
   масштаб = scale × fit
   центр (x, y) — в середину окна
   ```

   В окне меньше его экрана картинка уменьшается, в окне больше —
   растягивается; ничего из того, что видел ведущий, не обрезается.
   Нет `width`/`height` (записи до этой правки) — масштаб `scale` как
   есть; нет вида вовсе — подгонка под всё содержимое.
4. Нарисовать `items`, поверх — штрихи из `live`.
5. **Поля вокруг кадра, как у видео.** Всё за пределами области, которую
   видел ведущий, закрашивается нейтральным фоном (`--surface-2`), по
   краю кадра — тонкая линия (`--line`). Иначе на экране другой формы
   по бокам была бы видна доска, которой у ведущего не было.

Поворот телефона:

- **у смотрящего** — окно проигрывателя меняет форму, и кадр сразу
  вписывается заново (перерисовка по изменению размера окна, а не только
  по шагу записи: на паузе проигрывателя шага можно ждать сколько угодно);
  кадр тот же, меняются только поля;
- **у ведущего во время записи** — меняется размер его видимой области,
  он уходит в запись очередным `ViewportChanged`; при просмотре в этот
  момент кадр меняет форму (был высокий — стал широкий), как видео,
  снятое с поворотом.

## 8. Сервер: методы (онлайн-версия, SignalR-хаб)

| Метод | Кто | Что делает |
|---|---|---|
| `StartRecording(title, seedExisting, pageId, x, y, scale, width, height)` | владелец | §4.2; ответ всем — `RecordingStarted { id, title, startedAt, status }` |
| `PauseRecording()` | владелец | §3.2; всем — `RecordingPaused` |
| `ResumeRecording()` | владелец | §3.2; всем — `RecordingResumed` |
| `StopRecording()` | владелец | §3.2; всем — `RecordingStopped` |
| `ReportViewport(pageId, x, y, scale, width, height)` | владелец | дописать `ViewportChanged` |

Каждый вход/переподключение/синхронизация отдаёт клиенту текущую запись
(`{ id, title, status }` или пусто) — кнопки у всех показывают верное
состояние даже у того, кто пришёл посреди записи.

HTTP: список записей доски, одна запись со всеми шагами (для
проигрывателя), переименование, удаление (только остановленной), общий
список «Мои записи» по всем доскам.

`OpenPage(pageId)` (открыть страницу) у владельца при незавершённой
записи дописывает в неё `PageShown` со всем содержимым страницы.

Список записей в панели «Записи занятия» — по 10 на страницу, листалка
та же, что в «Моих досках» (в начало, назад, ±2 номера, вперёд, в
конец): записей на доске до 50 по тарифу.

## 9. Перенос в ПК-версию — что важно сохранить

ПК-версия — отдельная программа; сервера и участников у неё может не
быть. Тогда «сервер» из этого документа — это просто модуль записи внутри
программы, а «все участники» — один человек. Правила от этого не
меняются:

1. **Запись = журнал событий с отметками времени**, а не видео. Отметка —
   от начала записи **без учёта пауз** (§3.2): храните накопленную
   длительность и момент последнего продолжения.
   **Пауза вырезает только время**: результаты действий на паузе
   (закреплённые объекты, сдвиги, удаления, правки, смена фона) пишутся с
   отметкой момента паузы, процесс рисования — нет.
2. **Старт — на паузе + отсчёт 3-2-1 на месте кнопки** (§4.1). По концу
   отсчёта — «продолжить». Всё, что нарисовано после «1», — в записи;
   отсчёт в запись не попадает.
3. **Стартовое состояние — одним пакетом в нулевую миллисекунду**:
   первым вид (страница, центр, масштаб, размер видимой области), затем
   фон с разлиновкой (всегда), затем все объекты страницы (если выбрано
   «начать с уже нарисованного»). Никаких
   поштучных шагов с растущей отметкой.
4. **Вид записывается по ходу** — при каждом изменении, с прореживанием
   (онлайн — 300 мс), вместе с размером видимой области; при продолжении
   после паузы — сразу текущий.
5. **Управление записью — отдельным блоком у «Участников»**, а не в
   панели инструментов (§6), вне потока — «Участники» не двигаются.
   Оформление: зелёный мерцающий (идёт), зелёный ровный с цифрой по
   центру (отсчёт), голубой ровный (пауза); фон непрозрачный; наведение —
   тем же цветом, гуще.
6. **Автоматика** — §5.2 в переложении на ПК:
   - закрытие окна/выход из программы → остановить и сохранить запись
     (в ПК-версии нет «перезагрузки страницы», поэтому паузы на этот
     случай не нужно);
   - сворачивание/переход в другое окно → запись **не** трогать (урок
     может идти с показом другого окна);
   - аварийное завершение → при следующем запуске незавершённую запись
     закрыть как остановленную (длительность — по последнему шагу).
7. **Проигрыватель** — §7: чистая функция применения шага, кэш состояния
   для перемотки, в позиции 0 уже виден seed, вид — глазами ведущего,
   **вписан целиком** в окно проигрывателя, вокруг — поля (§7.3);
   перерисовка и при изменении размера окна.
8. **Переход на другую страницу во время записи** — снимок её
   содержимого в запись (`PageShown`, §7.1).

### Проверка после переноса

- [ ] Нажали «Начать запись» → слева от «Участников» сразу 3, 2, 1 (цифра
      по центру) на зелёном, без мерцания; затем «Пауза» и «Стоп» на
      мерцающем зелёном. «Участники» при этом не сдвинулись.
- [ ] Нарисовали сразу после «1» — штрих есть в записи, с процессом.
- [ ] Рисовали во время отсчёта — в записи это есть в 0:00, сразу готовым.
- [ ] С галочкой: в проигрывателе в 0:00 уже всё старое содержимое, без
      «дорисовывания», и вид сразу как у ведущего.
- [ ] Без галочки: фон и разлиновка в записи — как у ведущего.
- [ ] Пауза на 10 секунд → в записи в этом месте нет пустых 10 секунд.
- [ ] На паузе нарисовали и сдвинули → в записи это появляется разом в
      момент продолжения.
- [ ] Низ и края того, что видел ведущий, видны в проигрывателе целиком
      (окно проигрывателя ниже экрана ведущего); вокруг кадра — поля.
- [ ] Повернули телефон при просмотре (в т. ч. на паузе проигрывателя) →
      кадр тот же, сразу вписан заново.
- [ ] Ведущий повернул телефон во время записи → при просмотре кадр в
      этот момент меняет форму.
- [ ] Во время записи перешли на другую страницу, где уже что-то
      нарисовано, и обратно → в записи на каждой странице ровно её
      содержимое.
- [ ] Голубой ровный блок на паузе; наведение/нажатие — голубым гуще.
- [ ] Несколько рисующих (онлайн) → в записи штрихи всех.
- [ ] Выход с доски / закрытие программы → запись сохранена и есть в
      списке.
