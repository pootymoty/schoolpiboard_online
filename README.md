# SchoolPiBoard — онлайн-доска

Сайт с онлайн-доской для совместной работы: school-pi-board.online.

Самостоятельный продукт. С десктопным приложением (другой репозиторий) его
связывают только тема, автор и потенциальная аудитория — общего кода, общей
базы и общих учётных записей нет и не планируется.

| Папка | Что там |
|---|---|
| `server/` | ASP.NET Core 8 + PostgreSQL + Redis: учётные записи, подписки, доски, участники, приглашения, SignalR |
| `webapp/` | React + TypeScript + Vite: главная, регистрация, доски, профиль, правовые страницы |

## Что уже работает

- Регистрация с подтверждением почты (ссылка живёт час, учётная запись
  создаётся только после перехода по ней), вход, капча.
- Подписка: пробные 7 дней и тарифы 30/90/180/365 дней, оплата через
  Робокассу, отмена и автопродление, продление добавляет дни к остатку.
- Доски: создание, удаление, список по 10 на страницу, чужие помечены 🔗.
- Участники: приглашение по почте, роли владелец / редактор / просмотр,
  ссылки-приглашения (вход 7 дней, право правки у приглашённых 30 дней).
- Комната доски: видно, кто сейчас в ней; при обрыве связи клиент
  переподключается и получает состояние заново.
- Профиль: имя, пароль, управление подпиской, удаление учётной записи
  с подтверждением по почте.

## Чего ещё нет

- **Холста.** Доска пока показывает участников и место под холст: рисование,
  синхронизация объектов и блокировки — следующие этапы (2b–2e исходного ТЗ).
- **Автосписания.** Флаг автопродления хранится, но реальное рекуррентное
  списание требует подключения соответствующего интерфейса платёжной системы —
  см. `docs/robokassa-recurring.md`.
- **Капчи.** Код проверки написан, но Yandex SmartCaptcha пока недоступна
  для подключения, поэтому проверка выключена и включается одним значением
  в конфиге.
- **Анимации фона** на главной: полки нарисованы статично, место для анимации
  подготовлено в одном компоненте.

## Развёртывание

Планируемое место на сервере: `/var/www/schoolpiboardon`.

```
/var/www/schoolpiboardon/
  api/     <- результат dotnet publish из server/SchoolPiBoard.Online
  web/     <- содержимое webapp/dist
```

Нужны PostgreSQL (отдельная база от десктопного сервиса) и Redis.
Веб-приложение — статика, её раздаёт nginx; API работает отдельным процессом
(systemd) и проксируется nginx по пути `/api` либо на поддомене.

Важно: для SignalR в nginx нужно разрешить WebSocket
(`proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade";`).

Подробности — в `server/README.md` и `webapp/README.md`,
развёртывание — в `docs/deploy.md` и `docs/runbook.md`.

## Сборка и обновление сервера

Сервер остаётся чистым: только рантайм ASP.NET Core, PostgreSQL, Redis и
nginx — ни SDK, ни Node.js, ни исходников, ни git. Сборка идёт на стороне
GitHub Actions (`.github/workflows/online-board.yml`): каждый пуш в `main`,
затрагивающий `server/` или `webapp/`, собирает бэкенд и фронтенд и кладёт
готовый архив в релиз `online-board-latest`. На сервере обновление — три
шага:

```bash
curl -sL -o ob.tar.gz https://github.com/pootymoty/schoolpiboard_online/releases/download/online-board-latest/online-board.tar.gz
sudo tar -xzf ob.tar.gz -C /var/www/schoolpiboardon
sudo systemctl restart schoolpiboardon
```

Архив внутри уже разложен на `api/` и `web/`, поэтому распаковывается прямо
в корень `/var/www/schoolpiboardon`.
