# SchoolPiBoard Web

Совместная доска в браузере для проведения занятий: `board.school-pi.online`.

Преподаватель открывает доску, даёт обучающемуся ссылку, оба рисуют и пишут
на одном холсте в реальном времени. **Обучающемуся регистрироваться не
нужно** — он заходит по ссылке и называет только имя.

Продаётся по подписке: платит тот, кто создаёт доски.

| Папка | Что там |
|---|---|
| `server/` | ASP.NET Core 8 + SignalR, PostgreSQL, Redis |
| `webapp/` | React + TypeScript + Vite |
| `deploy/` | юнит службы, конфиг nginx, образец `.env` |
| `docs/` | задание и протокол с сервером ключей |

Развёртывание — `DEPLOY.md`. Задание — `docs/spec.md`.

## Отношение к соседним продуктам

Три службы на одной машине, связанные только машиной и почтовым ящиком:

- **`school-pi.online`** — платформа на Flask под gunicorn. Доска отдельная
  служба намеренно: gunicorn запущен с одним рабочим процессом, и поток
  сообщений доски задушил бы сайт целиком.
- **`keys.school-pi.online`** — сервер ключей. **Владеет всей платёжной
  обвязкой:** пароли Робокассы лежат только там, доска в Робокассу не ходит
  вовсе — см. `docs/license-server-protocol.md`.
- **Десктопная доска** — отдельная программа по разовой лицензии. Веб-доска
  её не заменяет, а дополняет.

## Состояние работы

Задание разбито на этапы (раздел 11 в `docs/spec.md`).

| Этап | Что входит | Состояние |
|---|---|---|
| 11a | учётные записи, подтверждение почты, вход, развёртывание | сделано |
| 11b | доски, ссылки с ролями, вход гостем, права | следующий |
| 11c | холст, рисование, блокировки, курсоры | — |
| 11d | перо и нажим, картинки в Object Storage | — |
| 11e | тарифы, подписка, оплата через сервер ключей | — |

Страница списка досок пока показывает заглушку: она подтверждает, что вход
состоялся, и не притворяется, будто доски уже есть.

## Сборка

Собирает GitHub Actions, сервер остаётся без SDK и без Node.js: в релиз
`online-board-latest` кладётся архив с готовыми `api/` и `web/`, откуда его
забирает `curl`. Обновление на сервере — четыре команды, они в `DEPLOY.md`.

Миграции применяются отдельной командой при выкладке, а не при старте
службы: выкладка и изменение схемы — разные события.

Модель и миграции пишутся вручную, поэтому сборка проверяет их согласие
командой `dotnet ef migrations has-pending-model-changes` — разойдутся,
и сборка станет красной до того, как разойдётся база.
